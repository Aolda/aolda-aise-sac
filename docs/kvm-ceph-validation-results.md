# KVM·Ceph 보완 검증 결과

검증일: 2026-11-26 ~ 2026-11-27 (Asia/Seoul). 결과는 보완 브랜치 소스 기준이며 운영 클러스터 전체 적용 완료를 뜻하지 않습니다.

## 로컬 시험

- 단위·계약·로컬 통합 시험: 63/63 통과. 실제 임시 파일 통합 3개, 상태를 가진 Ceph 대체 명령 통합 3개 포함.
- 대표 결함 주입 검출: 12/12 (100%). 코드 줄/분기 커버리지나 모든 가능한 결함의 검출률은 아닙니다.
- KVM/Ceph 기본 실행 파일 2개 및 원격 격리 시험 파일 문법 검사 통과.
- 기존 localhost 보고서 회귀 시험 통과. 기존 역할 출력 형식을 유지합니다.
- SSH 정책 내용이 같아도 권한이 0777로 바뀐 경우 0644로 복구되는 회귀 시험을 추가했습니다.

## 기존 시험 서버 확인

사용자가 이전 대화에서 지정한 DevStack 시험 서버를 재사용했습니다. 인증키는 로컬 SSH 인증에만 사용하고 서버 주소·키 경로·개인키·토큰은 저장소 시험 자료에 포함하지 않습니다.

- Ubuntu 24.04.4, libvirt 10.0.0, QEMU 8.2.2.
- libvirt가 활성 상태이고 기존 `default` 네트워크는 active/autostart 상태입니다.
- 실행/등록 가상머신은 없습니다. 최초 시험 시 Ceph가 없었으나, 2026-11-27 사용자 추가 지시에 따라 Ceph 19.2.3 단일 노드 시험 클러스터를 설치했습니다.
- 실제 시험용 Ansible 인벤토리는 제어 컴퓨터의 임시 경로에만 두었습니다.

## 수행한 실환경 시나리오

|번호|시나리오|관측 결과|
|---|---|---|
|R01|두 역할 기본 보고 모드|ok=63, changed=0, failed=0, skipped=72|
|R02|실제 실행 파일에서 apply_policy=true + --check|변경 예정 4건, 실패 0건. 지정 임시 경로가 생성되지 않았음을 별도 SSH로 확인|
|R03|시험 keyring 권한 첫 적용·재적용·변조 복구|첫 변경 있음, 재적용 변경 없음, 0644 변조 후 0600 복구|
|R04|시험 개인키 권한|0600 적용, 재적용 후 ctime까지 동일|
|R05|실제 sshd를 이용한 독립 설정 점검 모드|기존 시험 파일 내용 보존|
|R06|독립 SSH 설정 첫 적용·재적용|실제 sshd -t/-T 통과, 재적용 변경 없음|
|R07|잘못된 SSH 구문 주입|예상대로 실패 후 원래 시험 설정 복원|
|R08|로그 스냅샷 반복 실행|첫 생성 있음, 같은 작업 ID의 두 번째 생성 없음|
|R09|별도 비활성 libvirt 네트워크 자동 시작 해제|첫 해제 변경 있음, 반복 해제 변경 없음|
|R10|별도 libvirt 네트워크 정의 삭제·정리|시험 네트워크 제거 확인, 기존 default 네트워크 유지|
|R11|설치한 실제 Ceph 인증 설정·권한·클라이언트|CephX 유지 상태의 설정 차이 복구, 반복 무변경, 실제 거부 코드 13, 허용된 객체 입출력 성공. 무인증 전환은 미수행|

격리 시험 전체 집계는 ok=89, changed=20, failed=0, ignored=1입니다. changed=20에는 시험 파일/네트워크 준비와 정리가 포함됩니다. ignored=1은 R07에서 의도적으로 넣은 잘못된 SSH 구문을 거부한 결과이며, 단순 무시 후 성공 처리한 것이 아니라 실패 여부와 원본 복구를 추가 assertion으로 확인했습니다.

독립 SSH 설정 시험은 임시 설정 파일에 실제 sshd의 검증 명령만 실행합니다. 운영 SSH 설정을 교체하거나 서비스를 재시작하지 않습니다. libvirt 시험 네트워크는 별도 이름으로 정의만 하며 활성화하지 않아 브리지/라우팅을 변경하지 않습니다. 원격 시험의 임시 디렉터리와 네트워크는 실행 후 정리했습니다.

## 수행하지 않은 실환경 유형

|번호|유형|미수행 이유|
|---|---|---|
|U02|다중 Ceph 노드 중지·정족수·복귀|단일 노드 시험 클러스터만 구성|
|U03|실제 패키지 업그레이드·하향 변경·재부팅|기존 DevStack 환경을 유지하기 위해 실행하지 않음|
|U04|실제 UFW 규칙 변경·IPv4/IPv6·접속 유지|호스트 방화벽을 변경하지 않음. 모듈 연결과 실행 계약만 검증|
|U05|SELinux 강제 모드·부팅 후 유지|해당 시험 환경 없음|
|U06|실행 중 가상머신 및 활성 네트워크 중지 영향|실행 가상머신 없음. 비활성 시험 네트워크 범위만 수행|

기존 U01 중 실제 Ceph 인증 설정·클라이언트 사용은 R11로 검증했습니다. 다만 무인증(`none`)에서 CephX로 전환하는 중단/재시작 시험은 하지 않았습니다. 따라서 기존 16개 유형 중 완전 수행 10개, 부분 수행 1개, 미수행 5개로 구분합니다. 부분 수행을 포함한 유형 실행률은 11/16(68.75%)이나 완전 수행률은 10/16(62.5%)입니다. 전체 구현/보안 커버리지와 다릅니다. 기존 대표 결함 검출률 12/12는 유지하며 이번 실제 Ceph 시험에서 별도 신규 결함 검출률은 측정하지 않았습니다.

## 기존 서비스 확인

시험 후 SSH 설정 문법, libvirtd/ssh 활성 상태, 기존 default 네트워크 유지 및 임시 파일 삭제를 확인했습니다. DevStack 토큰 발급, 서비스 목록, 컴퓨트 서비스, 네트워크 에이전트, 볼륨 서비스, 이미지 목록 조회가 모두 성공했습니다. 토큰과 비밀번호는 출력하지 않았습니다.

## 재실행

```bash
ansible-playbook tests/kvm_ceph/remote_fixtures.yml \
  -i /absolute/path/to/test-inventory.ini --limit test-host \
  -e baseline_test_confirmed=true
```

인벤토리는 `baseline_test` 그룹을 사용합니다. 시험 서버에는 Ubuntu 24.04, sudo, virsh/libvirtd, sshd 및 호스트 키가 필요합니다. 이 시험은 운영 서버에 실행하지 마십시오. 실패 시에도 always 정리 구간을 실행하지만 연결 상실·강제 종료 시 남은 자원은 운영자가 확인해야 합니다.

## 실제 Ceph 추가 검증

설치/재현 절차와 한계는 [Ceph 실환경 시험](ceph-live-lab.md)에 기록했습니다. MON/MGR/OSD 각 1개, 내부 주소 `127.0.0.1`, 3 GiB 일반 파일 저장소를 사용했습니다. 기존 패키지 업그레이드·제거는 없고 신규 패키지 47개를 설치했습니다.

- 실제 인증·권한·입출력 시험 최종 실행: ok=74, changed=8(주입·복구·시험 쓰기·정리 포함), failed=0, ignored=0.
- 실제 구성 DB의 인증 설정 3개 첫 적용 변경 후 재적용 변경 없음. 보고 모드와 apply_policy=false에서 주입된 차이를 유지함을 확인했습니다.
- 실행 중 MON에서 CephX 값 확인. 관리자 keyring의 0640→0600 복구 후 재적용 변경 없음.
- 잘못된 인증키: 오류 코드 13 및 `RADOS permission denied`. 제한된 클라이언트의 관리 명령: 오류 코드 13 및 `EACCES: access denied`. 시간 초과나 임의 실패를 성공으로 세지 않았습니다.
- 허용된 풀에서 실제 객체 쓰기·읽기 후 바이트 비교 성공.

초기 설치/시험 준비 과정에서 데이터 배치 계층 누락, 기본 인증 목록 차이 및 실제 오류 메시지 표기 차이를 확인하고 수정했습니다. 중간 실패 실행을 최종 통과 건수에 합산하지 않았습니다. 작업 단위 점검 설정은 전역 점검 변수와 달라 검증 assertion이 실행될 수 있어, 지원하는 실제 명령줄 `--check`를 별도 검증합니다.

### 추가 실행별 최종 집계

|실행|ok|changed|failed|판정|
|---|---:|---:|---:|---|
|실제 클라이언트 키 배포·재배포|33|2|0|최초 배포·정리만 변경. 반복 시 ctime/파일 식별자 동일, 배포 키로 읽기 성공|
|점검 시험 차이 주입|9|2|0|인증 목록·설정 파일 권한 변경|
|실제 명령줄 --check|41|1|0|파일 변경 예정 1건. 인증 command 작업은 점검 모드에서 건너뜀|
|점검 후 독립 조회|7|0|0|인증 목록과 파일 권한이 주입 상태 그대로 유지됨|
|전체 역할 첫 적용|44|2|0|인증 설정 1건·파일 권한 1건 복구|
|전체 역할 동일 조건 재적용|43|0|0|변경 없음|
|전체 역할 보고 모드|37|0|0|변경 없음|

모든 최종 추가 실행의 unreachable/rescued/ignored는 0입니다. 전체 역할의 계정·SSH·패치·SELinux 변경 기능은 꺼 두었습니다. 위의 `changed=0`은 시험한 인증·keyring·설정 파일 정책의 범위이며 전체 Ceph 기능이나 모든 환경의 멱등성 보장이 아닙니다.

추가 설치 후 기존 DevStack의 6종 조회와 SSH/libvirt/default 네트워크 확인이 성공했습니다. 기존 Cinder 루프 장치도 유지했습니다. Ceph는 정상 배치 상태(`active+clean`)이고, 남은 경고는 `.mgr`와 시험 풀의 복제본 없음(`POOL_NO_REDUNDANCY`)입니다. 시험 클러스터는 후속 검증을 위해 유지했습니다.
